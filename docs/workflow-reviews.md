# 持久化回答审批与图续接

## 使用流程

1. 聊天工作流在 `human_approval` 前暂停。后端保存审批任务，回复包含 `needs_human=true` 和 `review_task_id`；用户看不到草稿。
2. 管理员打开控制台的“回答审批”，刷新列表，输入任务 ID 查看原问题、证据和草稿。
3. 选择“批准并发送”或“拒绝并重新检索”，填写可选备注，提交决定。
4. 批准后，原图从暂停节点继续到结束，最终回答写入用户会话一次。拒绝后，原图执行改写、检索、生成和质量评估；再次不通过会建立一个新审批任务。
5. Gradio 客户聊天页轮询后端并显示最终回复；API/SSE 客户端通过查询接口获取结果。

“回答审批”对应真实暂停的图；原“人工介入管理/人工对话”保留处理直接转人工的投诉、退款等工单。带 `review_task_id` 的初始回答不会再由聊天 UI 重复创建旧工单。
若自动重试达到上限仍需人工，最终结果保留 `needs_human` 与交接包；Gradio 将其送入原人工对话流程，并以审批任务 ID 防止重复建单。

## API

| 方法与路径 | 权限 | 行为 |
|---|---|---|
| `GET /api/reviews?session_id=...` | 登录用户 | 查询自己的会话任务；管理员可查询全部 |
| `GET /api/reviews/{task_id}` | 任务所有者或管理员 | 所有者仅看到状态和已完成结果，管理员另有草稿与证据 |
| `POST /api/reviews/{task_id}/decision` | 管理员 | JSON：`{"decision":"approve","note":"核验完成"}` 或 `reject` |

任务状态为 `pending`、`processing`、`resolved`、`superseded`。可通过 `status` 参数筛选，列表返回最近 100 条。错误包括未登录 401、无审批权限 403、不可见任务 404、决定冲突或快照过期 409、非法参数 422、可恢复的执行失败 503。

用户侧查询不返回待审核答案、证据或管理员备注。会话与任务由已认证用户名绑定，不能通过请求体指定另一个所有者；权限降低时也不能通过查询接口获取原高权限任务结果。
同一任务重复提交同一决定会返回已保存结果，不重新生成或重复入库；改成另一决定返回 409。备注和实际操作人的用户名记录在任务中，重复请求不会覆盖首次审计信息。
手动批准是人工核验决定，不会伪造或提高原自动忠实度分数。

## 持久化与恢复

默认使用以下路径，均在 Docker Compose 已有的 `./data:/app/data` 挂载内：

| 配置项 | 默认文件/目录 |
|---|---|
| `WORKFLOW_CHECKPOINT_PATH` | `data/workflow_checkpoints.db` |
| `WORKFLOW_REVIEW_PATH` | `data/workflow_reviews.db` |
| `WORKFLOW_LOCK_DIR` | `data/workflow_locks/` |

生产 `get_workflow()` 工厂使用 SQLite saver；服务退出时关闭连接，再次创建工厂会重开同一数据库。`RAGWorkflow()` 不传 saver 时仍使用内存模式供隔离测试；独立脚本要持久化时显式传入 `build_checkpointer(path)`。
依赖已加入 `requirements.txt`、`pyproject.toml` 和 Poetry 锁文件。数据库、WAL/SHM 文件和锁目录均忽略 Git。

决定先写入审批表，再修改 checkpoint 和恢复图。图状态保存任务标识与已消费的决定，用于区分“尚未执行”和“拒绝后已到达下一次审批”，防止故障重试误批准/拒绝新草稿。
旧任务结果和新任务的发布在同一 SQLite 事务中完成；`processing` 任务恢复前，不允许新聊天覆盖会话图状态。
若处理失败或 HTTP 超时，管理员重试**同一任务、同一决定**。原处理中决定不会自动换成另一个决定。

完成结果先保存，再投递到会话；会话消息通过唯一 `event_id` 去重。投递中断可由重复审批、所有者查询或下次聊天补投，避免“已处理但用户没收到”以及重复回复。前端也按任务 ID 去重显示。
同一会话的聊天和审批共用线程锁与操作系统文件锁，支持同机进程间互斥；进程崩溃后操作系统释放锁。适用于本项目的本地/单机部署，未声称可跨不同主机协调。
恢复需要兼容的图结构和节点代码。故障发生在外部推理进行中时，该节点推理可能重跑；这里保证审批决定和最终会话投递的幂等，未宣称外部推理调用恰好一次。

## 验证范围

测试使用真实 LangGraph、SQLite saver、临时会话库及独立 Python 子进程；外部 LLM 和业务查询用受控替身。覆盖：

- 子进程读取暂停快照，重建图后批准；生产工厂关闭后重开同一快照。
- 批准/拒绝续接、拒绝后新草稿再次审批、待审批时新消息不覆盖图。
- 决定保存后/图执行后/投递中断后的恢复，以及旧决定不重复作用于新草稿。
- 并发管理员重试、跨进程文件锁、重复投递去重、过期快照拒绝。
- 管理员权限、所有者隔离、草稿隔离、UI 的审批 API 绑定与自动结果展示。
