# RAG 发布前检查

发布前运行两套真实 HTTP 对话评测。固定回归集用于发现与上一版的质量和 Token 差异，新题集用于检查此前未参与提示词调整的问法。脚本使用本地 BGE、项目配置的对话模型和隔离服务，订单后端和外网搜索关闭。

```powershell
python scripts/rag_release_gate.py --run-dir reports/rag-release/candidate-01
```

输出目录必须尚不存在。脚本将两个逐轮报告写入 `regression/report.json` 和 `release/report.json`，并生成汇总 `gate.json`。通过返回退出码 `0`，未通过返回 `1`，命令用法错误返回 `2`。首次运行需要项目可用的对话 API 配置和已缓存的本地模型。

仅重查已有报告时，可以传 `--check-only`。它会按当前数据及源码重新验证，无模型调用。报告中的源码指纹与当前代码不一致时，必须重新跑评测。

```powershell
python scripts/rag_release_gate.py --run-dir reports/rag-release/candidate-01 --check-only
```

## 判定规则

| 检查 | 要求 |
|---|---|
| 固定 18 轮 | 18/18 通过 |
| 新题 17 轮 | 至少 16/17 通过（90% 向上取整） |
| 两组风险与无证据题 | 所有要求转人工的题均满足其标注，风险漏拦为 0 |
| 两组证据 | 每道标有证据组的题都命中至少一条组内来源，各组均须命中 |
| 执行与用量 | 逐轮完整执行，响应、追踪和供应商 Token 对得上；缺用量或缺报告均失败 |
| 固定集 Token | 以短提示基线 51,834 为参考，预留 10% 波动，最多 57,018 |

10% 是本次为小样本设置的预算余量。新题没有历史对照，先记录全链路 Token，暂用相同的完整性要求。时延会受冷启动和供应商波动影响，当前门禁保留报告中的时延数据，用量以供应商返回的 Token 计。

判定器对当前数据集的原始问题和轮次逐一核对，按保存的响应重新计分，再核对逐次模型调用和汇总用量。它同时校验语料、模型和评测参数与基线是否可比，以及部署清单中的源码指纹是否属于当前工作区。更新固定语料、评测参数或模型时，需要按新配置重新建立可比基线并审查预算。

## 新题覆盖

`data/rag_release_eval.json` 在首轮执行前冻结，包含 15 段、17 轮。标注根据项目的 FAQ 及业务路由编写，涵盖预售与普通发货的条件切换、订单数量及支付、发票抬头、秒杀例外、历史订单多轮追问、部分证据、退款执行和食品安全。4 条风险题和 4 条证据不足题有 2 条重叠。

此集由开发侧标注，可以提供与历史调参题分离的发布信号。它未使用真实用户流量，关键短语、来源 ID 与转人工标记不能覆盖所有语义错误。发布仍需结合变更内容审查，尤其是涉及真实订单库或外部搜索的改动。

## 首次实测

| 指标 | 固定回归集 | 新题集 |
|---|---:|---:|
| 轮次通过 | 18/18 | 15/17 |
| 整段通过 | 12/12 | 14/15 |
| 风险漏拦 | 0/1 | 0/4 |
| 证据不足题通过 | 4/4 | 4/4 |
| 证据组通过 | 13/13 | 9/10 |
| 因同会话待审批而阻塞的轮次 | 0 | 1 |
| 全链路 Token | 51,511（预算 57,018） | 42,794 |

整体判定未通过，真实运行和最终版 `--check-only` 均返回 `1`。两条未通过轮次来自 `dialogue-401`。第一轮检索到了写有“预售以页面标注为准”的 FAQ-011，但系统将问题判为证据不足，没有回答去哪里核对。第二轮已改问普通现货，仍被同一条待审批任务阻塞，未进入检索。9/10 的证据组通过数也包含了这条因阻塞而无证据的追问。

数据和阈值保持实测前的版本。下一步可以用不同问法单独验证怎样区分有据可答的查询指引与订单实际状态，并检查用户明确切换条件后如何继续对话。
