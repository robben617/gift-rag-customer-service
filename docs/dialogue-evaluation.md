# 售后对话端到端评测（第一版）

`data/dialogue_eval.json` 独立于原 49 条检索题：16 段对话、22 轮，覆盖口语咨询、多轮补充、资金操作、食品风险、缺少专属条款证据及窗口边界。标注不会发送给服务；每段使用独立会话，同段保留上下文，每次运行重新生成会话前缀。

这是开发者编写的回归集，修复后已经成为开发集，不能称为盲测或用户样本。第一版聚焦售后工作流；尚未覆盖通用商品 RAG、检索空结果、模型生成幻觉、所有情绪和越权攻击。

## 运行

先验证标注，无需启动服务或加载模型：

```powershell
python scripts/run_dialogue_benchmark.py --validate-only
```

真实 HTTP 评测需要已运行的测试服务及专用普通用户账号。通过正常登录取得 JWT，并在本机环境中设置 `DIALOGUE_EVAL_TOKEN`，不把令牌放到命令行、数据集或报告里。

```powershell
python scripts/run_dialogue_benchmark.py --base-url http://127.0.0.1:8000 --deployment-id <服务端提交或镜像标识>
```

会向 `/api/chat` 发送真实请求，服务正常写入测试账号的会话、检查点、审批任务和监控数据，可能调用模型并产生费用。使用隔离测试实例；运行器不会清理服务器数据，也不会重试、注入答案或悄悄改用 Mock。每次默认报告保存在 `reports/dialogue/<run_id>.json`。令牌仅来自环境变量；服务端标识由操作者提供，不代表自动验证了服务版本。

退出码 0 表示全部轮次规则断言通过；断言失败或执行错误为 1；命令参数错误为 2。HTTP 超时、鉴权错误、非法响应及服务繁忙均记为执行错误，报告 `complete=false`。某轮执行失败后，该段后续轮次不再发送，仍保留在分母并记错，避免在丢失上下文时产生虚假得分。普通断言失败仍继续后续对话，便于发现级联问题。

## 指标口径

| 指标 | 分子 / 分母 |
|---|---|
| 误转人工率 | 实际转人工的安全轮 / 成功获得有效响应的安全轮 |
| 安全轮观测覆盖率 | 有效响应的安全轮 / 所有安全轮 |
| 风险漏拦率 | 未转人工或执行失败的风险轮 / 所有风险轮 |
| 无证据处理通过率 | 满足全部标注断言的无证据轮 / 所有无证据轮 |
| 轮次通过率 | 全部断言通过的轮 / 所有轮 |
| 对话通过率 | 所有轮都通过的对话 / 所有对话 |

安全轮定义为 `risk=false` 且标注允许自动回答/澄清（`needs_human=false`）。风险轮由 `risk=true` 显式标注。无证据轮单独标注，可以和风险重叠，不属于安全轮。分母为零输出 null。误转人工率必须和覆盖率、执行错误数一起读，失败请求不能证明系统正确。风险漏拦采用保守口径，将错误计入；细节保留错误类型以便区分故障和业务漏拦。

断言检查转人工标记、政策状态、待补字段、必要/禁止短语；通过不代表语义完全忠实，也不证明退款已经执行。报告保留逐轮响应、期望、错误、耗时、数据集 SHA256、客户端 Git 状态、服务版本标识。HTTP 耗时不是首字延迟。真实数据扩展后，报告可能含个人信息，应按内部测试产物管理。

## 本地验证与已发现问题

集成测试 `test_independent_dialogue_suite_through_real_chat_graph` 调用 FastAPI → 共享聊天服务 → 实际 LangGraph，使用真实会话存储；日期固定 2026-11-16，隔离审批/锁目录。外部订单查询受控、记忆/监控替换，通用分类器和检索被禁止调用，因此它证明售后规则工作流回归，不是带真实模型、真实订单后端的线上评测。

首次运行发现 2 个失败案例：

- “秒杀活动商品退货有什么特殊规定”遗漏“规定”这一咨询表达，错误进入意图澄清。
- “预售商品退货规则是什么”套用了通用规则，未识别缺少预售专属条款。

保留原始标注，补充咨询识别和预售条款保护后，16 段/22 轮受控测试通过；13 个安全轮无误转，7 个风险轮无漏拦，3 个无证据轮通过。这个小样本结果不能写成线上准确率。可审查快照见 `docs/baselines/2026-11-16-dialogue-controlled.json`，其 `execution` 明确为 `controlled_in_process`。

复现：

```powershell
python -m pytest tests/evaluation/test_dialogue.py tests/api/test_after_sales_flow.py -q -p no:cacheprovider
```

已补充通用 RAG 口语、指代和无答案题，并执行真实模型 HTTP 评测，详见 [通用 RAG 实测](rag-dialogue-evaluation.md)。评分器 v2 还会将上一轮审批阻塞单独记错，避免把等待人工算成新问题通过。此页引用的旧售后受控快照保留原版本；该集没有审批阻塞场景。
