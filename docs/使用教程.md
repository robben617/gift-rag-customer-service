## 第 0 课：这个项目是干什么的

**一句话**：这是一个**电商客服机器人**——顾客提问 → 系统从"知识库"找出最相关的资料 → 让 DeepSeek 大模型根据资料写回答 → 自动检查有没有"胡说八道"，必要时转人工客服。

**四条处理路径（系统自动路由）**

```
顾客提问
  ├─ 退货/退款/政策类 ──→ 结构化政策工具直答（零幻觉，不检索）
  ├─ 含订单号/快递单号 ──→ 订单查询工具（MySQL，连不上自动用 mock）
  ├─ 商品/优惠券/规则/物流常识类 ──→ RAG：检索知识库 → LLM 引用作答
  ├─ 闲聊类 ──→ 直接闲聊回复
  └─ 投诉/辱骂/情绪激烈 ──→ 安抚 + 生成工单转人工
```

**本地改造版技术栈**

| 组件 | 用什么 | 说明 |
|------|--------|------|
| 向量库 | **Chroma**（本地 `data/chroma`） | 替代原 Milvus，无需 Docker |
| 向量化 | **本地 bge-small-zh-v1.5**（512 维） | 把文字变成向量 |
| 精排 | **本地 bge-reranker-base** | 检索后再精排一次 |
| 主 LLM | **DeepSeek**（deepseek-chat） | 意图识别、生成回答、幻觉检测 |
| 联网兜底 | **Tavily** | 知识库查不到时上网搜 |
| 图片理解 | **SiliconFlow** `Qwen/Qwen3-VL-8B-Instruct` | 图片 → 文字描述入库 |
| 扫描件 OCR | **RapidOCR**（本地） | PDF 扫描页 → 文字 |
| 缓存 | Redis（可选，未启动自动用内存缓存） | |

**当前知识库状态**：`data/faq/ecommerce_kb.json`（60 条客服问答）已入库为 **61 个向量**，库名 `ecommerce_knowledge`。

## 第 3 课：登录鉴权与知识检索

**为什么登录？** 系统有 4 级用户，登录后发一个 **JWT token**（加密"身份证"，含用户名/角色/等级/过期时间），每次请求带着它，服务端就知道你是谁、能看什么内容。

**4 个演示账号**

| 账号 | 密码 | 角色 | 内容等级 |
|------|------|------|----------|
| admin | admin123 | 管理员 | vip（可管理） |
| vip | vip123 | VIP | vip |
| member | member123 | 会员 | member |
| normal | normal123 | 普通 | public |

**实测三步**（可用 `scripts/demo_auth_query.py` 复现）

```
【第1步】不带 token 直接检索
HTTP 401 → {'detail': '未提供认证凭据'}

【第2步】登录拿 token
POST /api/auth/login {"username":"admin","password":"admin123"} → HTTP 200
access_token: eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ...（一长串）

【第3步】带 token 检索「怎么退货」
POST /api/query → HTTP 200，命中 3 条，来源 ecommerce_kb.json
第1名 相似度≈0.66  第2名 相似度≈0.71  第3名 相似度≈0.61
```

要点：
- 相似度 ≈ 0.6~0.7 就算高度相关（余弦相似度，量纲与旧 Milvus 不同，阈值已调到 0.4）。
- **顺序不完全等于分数顺序**：检索后本地 bge-reranker 会再精排一次，`score` 保留的是粗筛分。
- 每条结果都标**来源文件**——回答可溯源。

**推荐工具：Swagger** —— 浏览器打开 `http://127.0.0.1:8000/docs`，点 Authorize 登录后，可以点点点调所有接口，最直观。

## 第 4 课：智能对话（核心）与两条回答路径

接口：`POST /api/chat`（body: `{"query":"...","session_id":"..."}`，需 token）。

**实测对比（scripts/demo_chat.py）**

```
问「怎么退货？」            → 意图 return_refund，检索 0 条
问「优惠券能和其他券叠加吗？」 → 意图 product_consult，检索到 5 条资料
问「能指定快递公司吗？」     → 意图 logistics，检索到 5 条资料
```

**关键理解：系统有两条"知识"路径**
1. **业务工具直答**（退货/退款/订单）——检索 0 条是**设计如此**：政策工具用写死的规则回答，零幻觉。此时 `faithfulness` 显示 0.0 属正常（不是基于文档生成的回答）。
2. **RAG 检索作答**（商品/优惠券/物流常识…）——会显示"检索到 N 条资料"，DeepSeek 的回答带 **`[1][2]` 引用角标**，可溯源到具体是哪条 FAQ 支撑的。

**聊天响应里常见字段**

| 字段 | 意思 |
|------|------|
| intent / confidence | 识别出的意图（6 类）与置信度 |
| reply | 最终客服回答 |
| results | 用到的知识库资料（来源/相似度/原文） |
| rewritten_query | 改写后的问题（多轮指代消解时非空） |
| faithfulness | 回答对资料的忠实度（0~1） |
| degradation_method | 检索方式：decomposed / dense / rewritten / expanded / web_search / fallback |
| needs_human / human_reason | 是否转人工及原因 |

**6 类意图**：`return_refund`（退货退款）/ `order_query`（订单）/ `logistics`（物流）/ `product_consult`（商品）/ `complaint`（投诉）/ `chitchat`（闲聊）。

## 第 5 课：高阶对话能力实测

> 以下均为本机真实输出（scripts/demo_lesson4.py 可复现）。

### 5.1 订单查询工具（MySQL 不可达自动降级 mock）

```
问：帮我查一下订单 ORD20260701001 到哪了？  （admin）
答：订单 ORD20260701001：已发货
   - 下单时间: 2026-07-01 10:23
   - 订单金额: ¥299.00
   - 承运商: 顺丰速运 (SF1234567890)
   - 预计送达: 2026-07-05
```

- 可用 mock 单号：`ORD20260701001`（已发货/顺丰 SF1234567890）、`ORD20260701002`（待发货）、`ORD20260701003`（已签收/圆通 YT9876543210）；物流单号 `SF1234567890`。
- 你没装 MySQL 也能演示——连不上自动用内置 mock（源码 `src/orders/order_service.py`）。
- 安全设计：mock 订单归属 normal 账号（seed_user_id=1），**非管理员只能查自己的订单**（防枚举单号）。

### 5.2 情绪识别 → 转人工

```
问：你们什么垃圾公司，我要去12315投诉你们！（normal）
情绪: extreme | 需要转人工: True
原因: 用户情绪极端（辱骂/威胁/法律升级），需人工介入
交接包: user_query/intent/emotion/entities/memory_summary/attempted_actions/unresolved_reason
答：非常抱歉给您带来不好的体验…正在为您转接专属客服专员处理…
```

**转人工交接包**会自动带上：用户原话、意图、情绪、抽取的实体、已尝试的动作——真人客服接手时不用再问一遍。

### 5.3 多轮记忆（同一 session_id 的两轮对话）

```
[第1轮] 问：我上周领了一张满300减50的优惠券（member）
[第2轮] 问：上次那个券怎么用？（同一 session）
        答：…（正确理解"上次那个券"=满300减50券）
        改写后问题: 优惠券使用方式   ← 指代消解生效
```

三层记忆：最近 6 轮原文保留 + 窗口外滚动摘要 + 实体账本（"上次那个券"靠实体表解析）。会话按 `{用户名}:{会话id}` 隔离。

### 5.4 高敏承诺护栏（退款/价格承诺不轻诺）

```
问：退款几天能到账？
意图: return_refund | 需要转人工: True
原因: 涉及资金操作，需要人工确认
答：您的退款请求已收到。为了确保资金安全，我们将为您转接人工客服处理退款事宜…
```

系统对**资金类承诺**设护栏：忠实度不足 0.85 就不让 AI 拍胸脯承诺，转人工核验（`src/generation` + `graph/workflow.py` 的 human_approval 节点）。

## 第 6 课：知识库入库（往脑子里加料）

### 方式 A：入库平台界面（http://127.0.0.1:7860，admin/admin123）
1. 点"上传文件"选择/拖入文档（支持 PDF / Word / Excel / PPT / 图片 / FAQ JSON / 网页 / TXT / MD，可多选）；
2. 右侧预览确认解析出的文字；
3. 点 **🚀 存入当前文件**（或 📦 批量全部入库）；
4. 入库状态显示"✅ 入库成功 …→ N 向量"。

### 方式 B：API 上传（管理员）——实测生命周期（scripts/demo_upload.py）

```
入库前向量数: 61
POST /api/upload/file 上传 demo_mount.md → status=ok | 分块 1 | 入库 1
入库后向量数: 62
检索「磁吸手机支架支持什么机型」top1 → 命中刚入库的文档 ✅
DELETE /api/documents/{source_file} → deleted: 1
删除后向量数: 61
```

> 说明：入库 = 解析文本 → 切分 chunk → bge 向量化 → 写 Chroma。同源重传会自动先删旧数据再插（增量更新）；上传接口会把文件名用内容哈希唯一化，避免同名互删。

### FAQ JSON 入库最省事

格式（本仓库的 `data/faq/ecommerce_kb.json` 就是 60 条示例）：
```json
[
  {"question": "怎么申请退货？", "answer": "登录账户，进入我的订单…", "keywords": ["退货","申请"]}
]
```
重新入库命令：`& 'python' scripts/ingest_faq.py`

### 图片 / 扫描 PDF 会被怎么处理（已实测）
- 图片 → SiliconFlow Qwen3-VL 生成中文描述 → 描述入库；
- PDF：有文字层的走"文本快路径"，**含有效图片/纯扫描的页**走 RapidOCR 本地识别 → 文字入库；
- 实测：一份扫描版证书 PDF 被 RapidOCR 完整提取出姓名、编号、有效期等字段，一张实物照片被 Qwen3-VL 准确描述。

## 第 9 课：权限模型（为什么有 4 个账号）

```
内容等级：public(0) < member(1) < vip(2)
可见规则：用户等级 >= 文档等级 才可见
```

- 入库时可给文档打标签（`access_level: public/member/vip`）；
- 检索时按用户等级过滤（`access_level <= 用户等级`），vip 文档对普通用户**不可见、进不了召回集**；
- 缓存 key 也带等级，不同权限用户不串缓存；
- fail-safe：漏传等级默认按最低权限 public。

**如何看效果**：用 `normal` 登录 vs `vip` 登录调同一个 `/api/query`，vip 用户能多检索到会员/VIP 级文档（当前 60 条 FAQ 全是 public，所以结果相同——想验证可以先入库一条 `access_level=vip` 的文档再对比）。

## 常见问题 FAQ

**Q1：服务起不来/端口占用？**
`netstat -ano | findstr :8000` 找 PID → `taskkill /PID xxx /F`；或换端口（改 .env 的 API_PORT 并同步 API_BASE_URL）。

**Q2：控制台中文乱码？**
运行 python 前加 `$env:PYTHONIOENCODING='utf-8'`。

**Q3：检索结果为空？**
① 知识库空 → 跑 `scripts/ingest_faq.py`；② 阈值太高 → `.env` 加 `RETRIEVAL_SIMILARITY_THRESHOLD=0.3`；③ 权限——用 normal 登录只能看到 public 内容。

**Q4：Redis 提示连不上？**
正常，自动降级内存缓存。要启用：装好 Docker Desktop 后 `docker run -d --name rag-redis -p 6379:6379 redis:7-alpine`。

**Q5：chat 显示"检索到 0 条"？**
退货/退款类问题走政策工具直答，属正常；商品/优惠券类会走 RAG 并显示条数。

**Q6：faithfulness 一直是 0？**
工具直答路径没有文档可比对；RAG 路径若 LLM 打分失败会回退，可看服务端日志（logs/）定位。

**Q7：图片解析报"Model does not exist"？**
SiliconFlow 模型名要改成你账号下真实存在的（现在用 `Qwen/Qwen3-VL-8B-Instruct`；查可用模型：`& $py scripts/debug_sf_models.py`）。

**Q8：换了个新知识库想清空重建？**
删除 `data/chroma` 目录后重启 API，再重新入库。
